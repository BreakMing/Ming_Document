### CAN和CANOPEN的区别

简单来说 CAN只是规定了物理层和数据链路层，CANOPEN 不仅包括这些还完整定义了传输层、网络层、应用层的规范，让不同厂商的 CAN 设备无需定制开发即可实现互联互通，CANOPEN基于CAL协议开发而来的。

第一个是起始位，默认为0，然后接下去是仲裁段，包含11位的ID和RTR位，刚才发送的是0x230，这边解析出来也是0x230，RTR位为判断位，用来判断这一帧数据是数据帧还是遥控帧。之后是控制段，包含IDE位、r0位和DLC位，IDE位为判断位，用来判断这一帧数据是标准帧还是扩展帧，r0位为保留位，不做任何用处，为未来扩展提供可能性，DLC位为数据长度码，通过这一位可以控制发送数据段的长度，紧接着是数据数据段，最高可发送8个字节的数据。然后是CRC段，包含CRC校验位和CRC界定符，CRC校验位发送的是15位的CRC校验码，而CRC界定符是为了和后面数据隔开。之后是ACK段，由ACK槽和ACK界定符组成，发送端在ACK段发送2个位的隐性位，接收到正确消息的单元在ACK槽发送显性位，通知发送端正常接收结束。最后是EOF帧结束段，由7个隐性电平组成，表示这一帧数据发送结束。


第一个是起始位，默认为 0，表示一帧数据的开始。

接下去是仲裁段，包含 11 位的 ID 和 RTR 位。刚才发送的 ID 是 0x230，在波形中解析出来的结果同样也是 0x230，与我们示例数据中的 230 相对应。紧接着的 RTR 位为 0，表示这一帧是数据帧，而不是远程帧。

之后是控制段，包含 IDE 位、r0 位和 DLC 位。其中，示例数据中的第一个 0 对应 IDE 位，表示这一帧是标准帧，而不是扩展帧；第二个 0 对应 r0 位，这是一个保留位，目前没有实际用途；接下来的 5 则是 DLC（数据长度码），表示后续的数据段包含 5 个字节 的有效数据。

紧接着是数据段，也就是我们真正需要发送的数据内容。在示例中，对应的就是 18、42、28、54、13 这 5 个字节，其数量与前面 DLC 的值完全一致，说明数据解析正确。

数据段之后是 CRC 段，它由 CRC 校验位 和 CRC 界定符 组成。其中 CRC 校验位是 15 位的校验码，用于检测数据在传输过程中是否发生错误；而 CRC 界定符则起到分隔作用，用来将 CRC 段与后续内容区分开。

接下来是 ACK 段，由 ACK 槽 和 ACK 界定符 组成。在示例数据中，0 对应 ACK 槽，表示总线上有节点成功接收到了该帧数据，并在此位置发送显性位进行应答；紧随其后的 1 为 ACK 界定符，用于标识 ACK 段的结束。

最后是 EOF 帧结束段，由 7 个连续的隐性电平组成。在示例中用 7F 来表示这一段，说明这一帧 CAN 数据已经发送完成。
